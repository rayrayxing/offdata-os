# Research, Innovation and Capability

## Venture creation sequence

`Frontier Scout + Trend Spotter → Technology Transfer → Context Translator → Venture Imagination → Entrepreneur-in-Residence → Initial Venture Thesis → Capability Architect → Skill/Tool Forge → Deep Research Cell → Research Dossier → Opportunity Architect → Contrarian #1 → Venture Refiner → Targeted Research → Business Model + Distribution + Customer Anthropology → Contrarian #2 → Experiment Designer → Prototype Authorization → Prototype → Commercial Validation → strict G3 → G4–G10`.

## Roles before idea critique

Contrarian #1 must not critique a frontier/domain thesis using only generic knowledge when domain expertise can be acquired. Capability Readiness occurs first.

### Capability Readiness
For each thesis identify:
- required domains and specialist knowledge;
- required primary/community/market sources;
- required tools and credentials;
- installed Skills and certification state;
- missing Skills/tools/data.

Resolution order:
1. existing certified Skill/tool;
2. trusted Hermes Skill candidate → inspect/security-test;
3. adapt/build Skill;
4. test via Skill Auditor;
5. mark readiness `READY`, `READY_WITH_GAPS` or `NOT_READY`.

Facts/current market claims do not belong in Skills. Skills are procedures.

## Deep Research Dossier

Required coverage:
1. enabling change;
2. technical maturity and failure modes;
3. industry structure;
4. candidate ICPs;
5. user/buyer/approver/blocker;
6. current workflow;
7. pain/cost;
8. existing spend/substitutes;
9. competitors;
10. regulation/trust/security;
11. distribution;
12. WTP proxies;
13. economics hypothesis;
14. historical attempts/failures;
15. contrary evidence;
16. unknowns;
17. recommended experiments;
18. source diversity/freshness/provenance.

## last30days

Install/use the current real Hermes-compatible last30days Skill to accelerate current research across supported communities/sources. It remains `MARKET_RESEARCH`, never direct-buyer authority. Preserve original source pointers/receipts. Provider failure must be recorded; never substitute synthetic `last30days.internal`-style results.

## Contrarian #1

Attack: false premise, technical feasibility, existing solution, customer inertia, economics, distribution, timing, incumbent response, regulatory/trust and novelty illusion.

Output ChallengeRegister with severity/confidence/evidence/mitigation/testability. Not a binary kill bot.

## Refiner

Convert valid criticism into product/ICP/wedge/trust/business-model/distribution changes where possible.

## Contrarian #2

Question: **Has the refined business earned the next unit of capital/learning?** Low-impact unresolved concerns remain tagged rather than automatically blocking.
