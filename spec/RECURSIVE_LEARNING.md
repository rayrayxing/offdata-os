# Recursive Learning

## Loop

`Outcome → AAR → LearningCandidate → Historian → FACT / PRIOR / PROCEDURE / POLICY_PROPOSAL`.

- FACT → canonical Venture Brain with evidence.
- PRIOR → analytics/calibration model.
- PROCEDURE → staged Skill candidate.
- POLICY_PROPOSAL → governed policy-change workflow; never automatic activation.

## Skill lifecycle

`DRAFT → TESTED → CERTIFIED → ACTIVE → DEPRECATED`.

Skill writes remain approval-gated during bootstrap/certification. A successful anecdote does not certify a Skill.

## Calibration

Material forecasts record outcome definition, probability, horizon, role/profile and model. Resolve later and compute Brier/proper scoring, calibration and bias. Connect decision results to economic outcomes where possible.

## Model routing evidence

Record task class, provider/model, cost, latency, schema validity, reviewer score, downstream result. Change role/task routing from evidence, not preference.

## Cross-venture learning

Historian detects repeated patterns across ventures and proposes priors/procedural changes. Evaluate later cohorts against earlier baselines to determine whether learning actually improves outcomes.

## Protected policy

Recursive learning may not silently rewrite evidence admissibility, G0–G10, finance, authority or security policy.
